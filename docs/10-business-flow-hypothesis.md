## 1. 想定される業務フロー

### 1-1. Excel 配布・回収フロー（現状）

```
①  人事部門が Excel を準備
    - メタデータ（発令日・会社情報 等）
    - 発令前データ（before）: 現在の組織・ポジション・メンバー
    - 発令後データ（after）: 空欄

②  旧組織単位に分割して担当部門長へ配布

③  担当部門長が after を記入
    「4月以降、自分の部門の人はどこに行くか」を入力

④  人事部門が回収・マージして全体を確認
```

**将来方向**: 回収・マージ工程を段階的に削減・撤廃し、ツール上での直接入力・リアルタイム連携に移行したい。

### 1-2. 初回インポート時の状態

after が空のため、ツール上では全員が「未アサイン」になる。  
**after を before のコピーで初期化**することが自然な出発点だが、組織コードが変わるケースがあるため単純コピーは不可。

## 2. 組織継承マッピングの必要性（仮説）

### 2-1. 旧組織 → 新組織の対応パターン

| パターン | 例 | 対応方法 |
|---|---|---|
| コード継続（多数派） | A001 → A001 | 自動検出（コード一致） |
| コード変更 | A001 → A001-NEW | 手動対応づけ |
| 分割 | B001 → B001-1 + B001-2 | 手動対応づけ＋個別割り振り |
| 統合 | C001 + D001 → E001 | 手動対応づけ |
| 廃止 | F001 → （消滅） | 対応なし＋メンバーを手動で移動 |
| 完全新設 | （なし） → G001 | 継承元なし |

### 2-2. 組織対応づけの位置付け

**「入力スタート支援」** として実装する。

- **いつ実行するか**: インポート直後（推奨）、または途中でやり直したい時
- **やり直しの意味**: 現在の編集内容を全クリアして再初期化（= リセット）
- **永続化**: しない（Excel ファイルベースの運用に合わせる）
- **AI支援**: 組織名・コードの類似度から対応候補を提案→ユーザーが確認・修正

### 2-3. 初期化ウィザードの想定フロー

```
Step 1: 旧組織ツリーと新組織ツリーを左右に表示
        コード一致 → 自動でライン引き（グレー）
        不一致   → 赤ハイライトで手動対応を促す
        AI 候補   → 名称類似度スコアで提案

Step 2: 分割・統合ケースのみ個別割り振り確認
        「旧B部(10名)→ 新B1部 or 新B2部 どちらへ?」
        ドラッグ or 一括指定 + AI推定（役職・レポートライン等）

Step 3: 適用
        after が初期値で埋まった状態でキャンバスが開く
        以降は通常の異動作業
```

## 3. 作業軸と照会軸（仮説）

### 3-1. 3つの視点

| 視点 | 用途 | 主な利用者 |
|---|---|---|
| **旧組織軸** | 「自分の部門の人をどこへ異動させるか」 | 部門長（配布先） |
| **新組織軸** | 「新しい部署に誰が着任するか」 | 新任部門長・人事確認 |
| **人軸** | 「田中さんはどこへ行ったか」 | 人事・管理職 |

### 3-2. 旧組織ベース比較ビュー（仮説）

旧組織を選択軸とし、after 状態をインラインで重ねて表示する。  
「着任予定」セクションで転入・新規採用も旧組織ビューに集約する。

```
選択: 旧 B部

                        ← 変更前    │  変更後 →
──────────────────────────────────────────────────
【継続メンバー】
  田中（部長）          B部・部長   │  新B1部・部長   [留任]
  鈴木（係長）          B部・係長   │  新B1部・係長   [留任]
  山田（一般）          B部・一般   │  新B2部・一般   [組織変更]

【離任予定】
  木村（一般）          B部・一般   │  ─────────────  [退職]

【着任予定】（新B部の継承組織に着任する人）
  高橋（一般）       A部から →    │  新B1部・一般   [転入]
  （空席）           新規 →       │  新B1部・課長   [新設ポジション]
──────────────────────────────────────────────────
```

**着任予定の表示ロジック（仮説）**:
- 組織対応づけ「旧B部 → 新B1部・新B2部」が定義されていること前提
- 新B1部・新B2部に所属する after-メンバーを逆引きして表示
- 継承元のない完全新設組織は「新設組織」セクションとして別表示

### 3-3. 表示モード

```
[ツリー表示]  [一覧表示]   ← 切り替え可能

ツリー表示:  旧組織の階層をそのまま表示
             各ノードに after 状態をインラインで表示
             「組織の構造変化」の把握に向いている

一覧表示:    変更のある人だけフラットに並べる
             差分フィルター・ソート付き
             「異動した人の全量把握」に向いている
```
