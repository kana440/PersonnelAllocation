# 23 — STEP1 組織照会・編集機能 要件定義書（デモ確認用・v3）

> **使い方**: この文書は、画面のデモを見せながら業務ユーザーに優先度を確認していくための資料。
> 1. 大分類（①〜⑫）ごとに「一言でできること」を説明する
> 2. 中分類ごとの要約表を見せ、画面をデモしながら「これがないとどう困るか」を確認し、**優先度欄に丸をつけてもらう**
> 3. 個別の項目まで確認したい場合だけ、その下の明細表を開く（時間がなければ中分類の丸つけだけで進めてOK）
>
> **実装の詳細（未実装・デッドコード・設計上のリスク等）はこの文書には書いていない。**
> 別紙 [`24-org-view-edit-known-issues.md`](./24-org-view-edit-known-issues.md) にまとめてあるので、構築者はそちらを参照。
> ここに載っている項目は全て「実際に画面で見せられるもの」だけに絞っている。

---

## 優先度の記入方法

各表の「優先度」欄は空欄になっている。該当するものに **◯をつける**か、該当しないものを線で消してください。

```
必須 ／ 条件付き ／ 対象外
```

| 選択肢 | 意味 |
|---|---|
| **必須** | これがないと現行業務が回らない。移植先に必ず必要 |
| **条件付き** | 業務は成立するが、なくすと効率・正確性が大きく落ちる。工数次第で判断 |
| **対象外** | 使わない／代替手段がある。移植しなくてよい |

## 全体像（大分類・作業の流れ順）

| # | 大分類 | 一言でできること |
|---|---|---|
| ① | データ取込 | Excel から発令前データを取り込む |
| ② | 組織照会 | 組織図・ナビで人と組織を把握する |
| ③ | 表照会・編集 | 一覧表で確認・編集する |
| ④ | データ出力 | Excel として結果を出力する |
| ⑤ | 編集機能 | ボタン操作で意味のある発令変更を行う |
| ⑥ | 項目自動導出 | 変更に連動して関連項目を自動更新する |
| ⑦ | バリデーション | データの不整合を検知する |
| ⑧ | 変更/エラーのみ確認 | 見るべき箇所だけに絞り込む |
| ⑨ | 一括エラー解除UI | 同種のエラーをまとめて直す |
