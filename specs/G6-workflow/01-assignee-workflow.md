# G6-01 担当者ワークフロー仕様

> **目的**: 担当者（assignee）フィールドを軸にした分割配布・編集・マージフローを定義する。
> 詳細な業務フローは `docs/10-business-flow-hypothesis.md` を参照。

---

## 1. 担当者フィールド（assignee）

### 1-1. フィールド定義

| 項目 | 内容 |
|---|---|
| フィールド名 | `assignee` |
| 型 | `string \| undefined` |
| Excel 位置 | A列（ヘッダーなし。現在は読み飛ばしている列） |
| マスタ | なし。ファイル内の既存値をリスト化して運用 |
| `prevXxx` | なし。`prevAssignee` は持たない（before 状態の概念ではない） |
| FieldBinding | `meta`（Excel 出力対象、変更検知対象外） |

### 1-2. 値の管理

- Excel インポート時に A列の値を `assignee` として読み取る
- ツール内で担当者リスト（ユニーク値）を保持・表示する
- 新規値の追加は UI のドロップダウンから自由入力で行う（マスタ追加不要）
- エクスポート時は A列に `assignee` を出力する

---

## 2. モード

### 2-1. 管理者モード

取りまとめ担当が使用するモード。

- 全行が表示される（担当者フィルタなし）
- 担当者フィールドの一括設定・変更が可能
- 担当者割り当てウィザードを使用できる
- 担当者ごとの分割エクスポートが使用できる
- 上司名補完サポート機能を使用できる
- マージ（追加インポート）が使用できる

### 2-2. 担当者モード

組織担当が使用するモード。自分の担当者名を選択して使用する。

- 選択した担当者名に一致する行のみが主表示対象
- 他担当者の行・未割当行はワーニング表示（参照可・担当変更可）
- 新規行を追加すると `assignee` が自動的に選択中の担当者名に設定される
- 担当者割り当てウィザード・分割エクスポートは非表示

### 2-3. モード選択UI（SetupView）

```
ファイル選択後に表示:

  ┌─────────────────────────────────────────┐
  │ どのモードで開きますか？                │
  │                                         │
  │ ○ 管理者として開く                      │
  │   担当者の割り当て・分割・マージを行う  │
  │                                         │
  │ ○ 担当者として開く                      │
  │   自分の担当行を編集する                │
  └─────────────────────────────────────────┘
```

担当者モードを選択した場合は AssigneeSelectStep（担当者選択画面）に遷移する。

## 3. AssigneeSelectStep（担当者選択画面）

OrgSelectStep を置き換える。担当者モード時のみ表示。

### 3-1. 表示内容

```
担当者を選択
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[担当者で絞り込み ▾]  [組織名で検索 🔍]

▼ 人事部担当                          計102行 [選択]
    人事部          100行
    出向者組織        2行

▼ 技術部担当                           計 83行 [選択]
    技術本部         80行
    出向者組織        3行

⚠ 未割当                               計  5行
    （担当者未設定行。新任者・例外など）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 担当者リストは `assignee` フィールドの既存値から生成
- 行数の内訳は `departmentCode`（after または prevDepartmentCode）でグループ化して表示
- 組織名検索：入力した組織名を含む担当者グループのみ表示
- 未割当グループ：`assignee` が空の行をまとめて表示

### 3-2. 担当者選択後の挙動

担当者を選択して「開く」を押すと：
1. 選択した担当者名を `activeAssignee` として設定
2. ワーニングチェックを実行し、結果を通知
3. 編集画面（OrgOperationView）を開く

### 3-3. ワーニング条件

操作は止めない。選択後に通知バナーで表示する。

| 条件 | メッセージ例 |
|---|---|
| 選択した担当者名以外の行が存在する | 「3行に別の担当者が設定されています。参照のみ可能です。」 |
| 未割当行が存在する | 「5行に担当者が設定されていません。新任者や例外行を確認してください。」 |

## 4. 担当者割り当てウィザード（管理者モード・実装済み）

`apps/web/src/components/header/AssigneeWizard/` に実装済み。設計時点の5ステップ案（分割軸選択 →
自動プレビュー → 出向者個別調整 → 未割当確認 → 確定）は、実装では **2ステップ**に簡略化されている。

**Step 1: 組織ツリーで設定**

- 旧組織ツリー（`beforeOrganizations`）を表示し、各ノードに「この階層を担当グループにする」
  チェック（`useThis`）を持たせる。デフォルトは第2階層が担当グループの単位
- 「一括設定: 第N階層」ボタンで全ノードのグループ階層を一括変更でき、その後ノード単位で個別調整できる
- 担当者名は組織名がデフォルト値。ノードごとに自由入力で上書き可能（`datalist` で既存担当者名を提案）
- 出向者・旧組織コード不明行の個別調整ステップは独立UIとしては存在せず、通常の担当者変更操作で代替する

**Step 2: 確認・適用**

- 担当者ごとの行数サマリーを表示し、「適用する」で `BulkSetAssigneeOperation` を実行（Undo 対象）
- 旧組織コードが不明な行（新任者等）は自動的にスキップされ、件数を表示する

未割当行の個別確認ステップは実装されていない（適用結果のスキップ件数表示のみ）。

---

## 5. 分割エクスポート（管理者モード・実装済み）

`apps/web/src/components/header/SplitExportButton.tsx` に実装済み。

- `assignee` ごとに行数を集計し、確認モーダルでチェックボックス選択（デフォルト全選択、未割当は選択不可）
- 選択した担当者ごとに Excel ファイルを1つずつ生成しダウンロード（`buildExportBuffer` を担当者でフィルタした行に適用）
- ファイル名・書式は通常の Excel エクスポートと同じロジックを再利用
- `capabilities.canSplitExport` が false のときはボタン自体を非表示にする（Feature Flag 制御）
- ❓ 未割当行専用の出力（取りまとめ担当向け）は未対応。現状は分割対象から除外されるのみ

## 6. 担当者モードのフィルタリング

### 6-1. useScopedStore の刷新

`useScopedStore` を `scopeOrgId` ベースから `activeAssignee` ベースに刷新する。

```typescript
// 旧（scopeOrgId）
const filteredRows = allocationList.filter(row =>
  scopeOrgIds.has(row.departmentCode)
)

// 新（activeAssignee）
const filteredRows = allocationList.filter(row =>
  row.assignee === activeAssignee
)
```

### 6-2. 他担当者行・未割当行の表示

担当者モード時に `assignee !== activeAssignee` の行は：
- レビュー画面・キャンバスで薄く表示するか、別セクションに分離する
- ワーニングアイコンを付与する
- 担当者変更ボタンを表示し、`activeAssignee` に変更できる

### 6-3. 新規行追加時の自動設定

担当者モードで新規行（新任者など）を追加した場合：
- `assignee` を `activeAssignee` に自動設定する
- ユーザーへの確認は不要（担当者モードでの新規追加は自分の担当が前提）

## 7. 上司名補完サポート（管理者モード・未実装）

各組織担当が `managerName`（上司の氏名フリーテキスト）を記入した後、取りまとめ担当がマージ時に
`managerPositionCode` を自動候補付きで確定するための補完機能。**未着手**。

要件:
- 対象: `managerName` はあるが `managerPositionCode` が未設定の行
- `managerName` を `allocationList` の氏名と突合し、完全一致 → 1件確定・あいまい一致 → 複数候補提示
  （同一組織の人物を優先表示）。❓ かな・漢字ゆれの吸収範囲は要確認
- 確定操作は `EditCommand` として実装し Undo 対象にする。一括確定と個別確認の両モードが必要

現状の代替: `BulkManagerPositionModal`（`apps/web/src/components/common/BulkManagerPositionModal.tsx`）は
選択した複数行に対して `PositionPickerModal` で上司ポジションを手動選択・一括設定できるが、
`managerName` テキストからの自動候補提示・あいまい一致検索は行わない。あくまで汎用の一括設定ツール。

## 8. 移行完了事項

- `scopeOrgId` / `setScopeWithMapping` / `orgScope.ts`（旧スコープ概念）はコードベースから削除済み。
  `activeAssignee` ベースに完全移行している（コード上に参照が残っていないことを確認済み）
- `OrgSelectStep` は `AssigneeSelectStep` に置き換え済み
- 担当者フィールド（`assignee`）は `prevAssignee` を持たない（変更履歴を追わない）
