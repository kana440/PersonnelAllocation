# G6-01 担当者ワークフロー仕様

> **目的**: 担当者（assignee）フィールドを軸にした分割配布・編集・マージフローを定義する。
> 詳細な業務フローは `docs/10-business-flow-hypothesis.md` を参照。

---

## 1. 担当者フィールド（assignee）

### 1-1. フィールド定義

| 項目 | 内容 |
|---|---|
| フィールド名 | `assignee` |
| 型 | `string \| undefined` |
| Excel 位置 | A列（ヘッダーなし。現在は読み飛ばしている列） |
| マスタ | なし。ファイル内の既存値をリスト化して運用 |
| `prevXxx` | なし。`prevAssignee` は持たない（before 状態の概念ではない） |
| FieldBinding | `meta`（Excel 出力対象、変更検知対象外） |

### 1-2. 値の管理

- Excel インポート時に A列の値を `assignee` として読み取る
- ツール内で担当者リスト（ユニーク値）を保持・表示する
- 新規値の追加は UI のドロップダウンから自由入力で行う（マスタ追加不要）
- エクスポート時は A列に `assignee` を出力する

---

## 2. モード

### 2-1. 管理者モード

取りまとめ担当が使用するモード。

- 全行が表示される（担当者フィルタなし）
- 担当者フィールドの一括設定・変更が可能
- 担当者割り当てウィザードを使用できる
- 担当者ごとの分割エクスポートが使用できる
- 上司名補完サポート機能を使用できる
- マージ（追加インポート）が使用できる

### 2-2. 担当者モード

組織担当が使用するモード。自分の担当者名を選択して使用する。

- 選択した担当者名に一致する行のみが主表示対象
- 他担当者の行・未割当行はワーニング表示（参照可・担当変更可）
- 新規行を追加すると `assignee` が自動的に選択中の担当者名に設定される
- 担当者割り当てウィザード・分割エクスポートは非表示

### 2-3. モード選択UI（SetupView）

```
ファイル選択後に表示:

  ┌─────────────────────────────────────────┐
  │ どのモードで開きますか？                │
  │                                         │
  │ ○ 管理者として開く                      │
  │   担当者の割り当て・分割・マージを行う  │
  │                                         │
  │ ○ 担当者として開く                      │
  │   自分の担当行を編集する                │
  └─────────────────────────────────────────┘
```

担当者モードを選択した場合は AssigneeSelectStep（担当者選択画面）に遷移する。

---

## 3. AssigneeSelectStep（担当者選択画面）

OrgSelectStep を置き換える。担当者モード時のみ表示。

### 3-1. 表示内容

```
担当者を選択
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
[担当者で絞り込み ▾]  [組織名で検索 🔍]

▼ 人事部担当                          計102行 [選択]
    人事部          100行
    出向者組織        2行

▼ 技術部担当                           計 83行 [選択]
    技術本部         80行
    出向者組織        3行

⚠ 未割当                               計  5行
    （担当者未設定行。新任者・例外など）
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

- 担当者リストは `assignee` フィールドの既存値から生成
- 行数の内訳は `departmentCode`（after または prevDepartmentCode）でグループ化して表示
- 組織名検索：入力した組織名を含む担当者グループのみ表示
- 未割当グループ：`assignee` が空の行をまとめて表示

### 3-2. 担当者選択後の挙動

担当者を選択して「開く」を押すと：
1. 選択した担当者名を `activeAssignee` として設定
2. ワーニングチェックを実行し、結果を通知
3. 編集画面（OrgOperationView）を開く

### 3-3. ワーニング条件

操作は止めない。選択後に通知バナーで表示する。

| 条件 | メッセージ例 |
|---|---|
| 選択した担当者名以外の行が存在する | 「3行に別の担当者が設定されています。参照のみ可能です。」 |
| 未割当行が存在する | 「5行に担当者が設定されていません。新任者や例外行を確認してください。」 |

## 4. 担当者割り当てウィザード（管理者モード）

### 4-1. 概要

取りまとめ担当が旧組織ツリーを見ながら担当者を一括割り当てするウィザード。
管理者モードのヘッダーまたはメニューから起動する。

### 4-2. ウィザードステップ

**Step 1: 分割軸の選択**

```
担当者の分割単位を選択してください

○ 統括部単位（部・Div レベル）
  → 旧組織ツリーの第2階層（トップ直下）を1担当者1グループとして自動提案

○ グループ単位（課・Section レベル）
  → 旧組織ツリーの第3階層を1担当者1グループとして自動提案

○ 自由設定
  → 自動提案なし。次のステップで手動割り当て
```

**Step 2: 自動割り当てプレビュー・調整**

- 旧組織ツリーを表示し、各ノードに自動提案した担当者名を表示
- ノードをクリックするとドロップダウンで担当者を変更できる
- 担当者名を新規入力すると新しいグループを作成できる
- 親ノードの担当者を変更すると子ノードも一括変更できる（選択制）

**Step 3: 出向者・例外の個別調整**

- `prevDepartmentCode` と `departmentCode`（after）が異なる行のリストを表示
- 各行に対して担当者を個別に設定できる

**Step 4: 未割当行の確認**

- `assignee` が空の行を一覧表示
- 「担当者を設定する」または「未割当のまま配布する」を選択できる

**Step 5: 確定**

- 担当者ごとの行数サマリーを表示
- 「適用する」で全行の `assignee` を更新する（Undo 対象）

---

## 5. 分割エクスポート（管理者モード）

### 5-1. 概要

担当者ごとに別々の Excel ファイルを生成してダウンロードする。

### 5-2. 挙動

- 担当者ごとに `assignee` が一致する行のみを含む Excel ファイルを生成
- 各ファイルの A列（担当者）は当該担当者名で統一される
- ファイル名: `{担当者名}_{発令日等}.xlsx`（❓ 命名規則は要確認）
- 未割当行は取りまとめ担当のファイルに含める or 別ファイルにするか選択できる（❓ 要確認）

### 5-3. 実装ポイント

- 元ファイルの書式（他シート・列幅等）は通常の Excel エクスポートと同様に保持する
- A列の担当者情報は各ファイルに含める（マージ時に担当者を識別するため）

## 6. 担当者モードのフィルタリング

### 6-1. useScopedStore の刷新

`useScopedStore` を `scopeOrgId` ベースから `activeAssignee` ベースに刷新する。

```typescript
// 旧（scopeOrgId）
const filteredRows = allocationList.filter(row =>
  scopeOrgIds.has(row.departmentCode)
)

// 新（activeAssignee）
const filteredRows = allocationList.filter(row =>
  row.assignee === activeAssignee
)
```

### 6-2. 他担当者行・未割当行の表示

担当者モード時に `assignee !== activeAssignee` の行は：
- レビュー画面・キャンバスで薄く表示するか、別セクションに分離する
- ワーニングアイコンを付与する
- 担当者変更ボタンを表示し、`activeAssignee` に変更できる

### 6-3. 新規行追加時の自動設定

担当者モードで新規行（新任者など）を追加した場合：
- `assignee` を `activeAssignee` に自動設定する
- ユーザーへの確認は不要（担当者モードでの新規追加は自分の担当が前提）

## 7. 上司名補完サポート（管理者モード）

### 7-1. 概要

各組織担当が `managerName`（上司の氏名フリーテキスト）を記入した後、
取りまとめ担当がマージ時に `managerPositionCode` を確定するための補完機能。

### 7-2. 対象行

- `managerName` が入力されているが `managerPositionCode` が未設定の行

### 7-3. 補完フロー

```
1. 管理者モードで「上司名補完」を実行
2. 対象行を一覧表示（managerName と現在の departmentCode を表示）
3. 各行について、allocationList の人員データから managerName で検索
4. 候補を表示（完全一致 → 1件、あいまい一致 → 複数候補）
5. 取りまとめ担当が候補を選択 → managerPositionCode を確定
6. 確定後は「補完済み」マーク。未確定行は「上司名未解決」ワーニングとして残る
```

### 7-4. 検索ロジック

- 第1優先: `managerName` と `localFullName`（または `localFirstName` + `localLastName`）の完全一致
- 第2優先: 部分一致
- 絞り込み候補: 同じ組織（`departmentCode`）に属する人物を優先して上位表示
- ❓ かな・漢字ゆれの吸収範囲は要確認

### 7-5. 実装ポイント

- 補完の確定は `EditCommand` として実装し Undo 対象にする
- 一括補完（全行を自動確定）と個別確認モードの両方を提供する

---

## 8. CLAUDE.md への反映事項

実装時の注意:

- `scopeOrgId` / `setScopeWithMapping` / `orgScope.ts` は **担当者ワークフローで置き換わる**
  - 既存のコードを参照している箇所を担当者ベースに順次移行する
  - 削除は担当者ワークフロー実装完了後に行う
- `OrgSelectStep` は `AssigneeSelectStep` に置き換える
- 担当者フィールド（`assignee`）は `prevAssignee` を持たない（変更履歴を追わない）
- 分割エクスポートは通常の Excel エクスポート層を再利用し、行フィルタのみ追加する
