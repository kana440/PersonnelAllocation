# /implement-spec — spec を実装する

以下の手順で spec を実装してください。

## 引数
$ARGUMENTS
（例: "specs/G3-ui/01-row-editor-input-spec.md P1" → specファイルパスと対象セクション）

## 手順

### 1. コンテキスト読み込み
1. CLAUDE.md を読む
2. specs/00-cross-cutting.md を読む（横断的影響チェックリスト）
3. 引数で指定された spec ファイルを読む
4. spec が参照している上位 spec（G1-fields, G2-domain）があれば読む

### 2. 影響範囲の特定
5. `specs/00-cross-cutting.md` の変更種別（A〜F）に照らし、今回の変更が影響する領域をリストアップする
6. 影響する領域ごとに対象ファイルを読んで現状を把握する

### 3. 実装
7. 対象の実装タスクを実装する（引数でセクション指定があればそのセクションのみ）
8. `specs/00-cross-cutting.md` で「必須」とされた関連領域も同時に更新する
9. `npx tsc --noEmit` を実行し、型エラーがあれば修正する

### 4. ドキュメント更新
10. 実装した spec ファイルのチェックボックス（`[ ]` → `[x]`）を更新する
11. 更新した関連 spec の実装状況も同様に更新する

## 実装の原則
- CLAUDE.md の「やってはいけないこと」を必ず守る
- spec の `❓` マーク（業務確認待ち）のタスクは実装しない
- 既存コードのパターンに合わせて実装する（新しい抽象を作らない）
- 実装後は必ず型チェックを通す
